# 이메일 초대와 회원가입 없는 채팅방 참여

회원 인증·방 생성에 이어 웹의 초대 생성·SMTP 발송·게스트 입장과 실시간 메시지 저장·송수신을 구현했습니다. 모바일 참여·대화 화면은 후속 구현입니다.

## 사용 흐름

1. 가입·로그인한 회원이 방을 만들고 해당 방의 OWNER가 됩니다.
2. 방장이 이메일을 입력하면 서버가 48시간 동안 한 번만 사용할 수 있는 초대를 만듭니다.
3. 메일에는 방 이름, 초대한 사람, 참여 버튼과 만료 시간을 포함합니다.
4. 수신자는 링크를 열어 내용을 확인하고 표시 이름만 입력해 참여합니다. 회원가입과 비밀번호는 요구하지 않습니다.
5. 명시적인 POST 수락에서 방 전용 GUEST 참여자와 7일 게스트 세션을 함께 생성합니다.
6. `/guest/rooms/:roomId`로 이동하며 같은 브라우저에서는 새로고침 후에도 참여 상태를 복원합니다.

초대 링크를 여는 GET이나 내용 조회는 초대를 소모하지 않습니다. 메일 보안 검사·미리보기 때문에 참여자가 먼저 생성되지 않습니다.

## 계정과 참여자

| 모델 | 책임 |
| --- | --- |
| User | 이메일 또는 구글로 로그인하는 회원 계정 |
| RoomMember | 방마다 독립 ID를 갖는 MEMBER/GUEST 참여자, 표시 이름, 역할, 퇴장 시점 |
| Invitation | 방, 수신 이메일, 초대한 회원, 토큰 해시, 만료·수락·취소, 발송 시도와 결과 |
| MemberSession | 회원 로그인 전용 세션 |
| GuestSession | 방과 참여자를 지정한 게스트 세션 |
| Message | 같은 방의 RoomMember를 작성자로 연결하는 메시지와 순번·재전송 ID |

게스트는 User를 생성하지 않습니다. 수신 이메일이 기존 회원 이메일과 같아도 자동으로 그 계정에 로그인시키거나 연결하지 않습니다. 각 방의 게스트 권한도 독립적으로 확인합니다.

## 권한과 상태

- 방 생성은 회원만, 초대 조회·발급·재전송·취소는 해당 방의 활성 OWNER 회원만 할 수 있습니다. 게스트 세션으로 회원 API를 호출할 수 없습니다.
- 초대 상태는 PENDING, ACCEPTED, EXPIRED, REVOKED입니다. 만료 뒤에도 이미 수락·취소한 상태를 유지합니다.
- 만료된 미사용 초대는 재전송할 수 있습니다. 이미 수락·취소한 초대는 재전송할 수 없습니다.
- 재전송은 기존 토큰을 폐기하고 새 48시간 링크를 만듭니다. 발송 성공 후에는 1분 후부터, 발송 실패 시에는 바로 재시도할 수 있습니다.
- 초대 취소는 새 참여를 막습니다. 이미 수락한 초대는 취소할 수 없으며, 기존 참여자 접근을 회수하는 관리 화면은 후속 구현입니다. 서버는 left_at이 설정된 참여자의 게스트 요청을 거부합니다.
- 수락·취소·재전송은 같은 DB 행을 잠가 조정합니다. 참여자·세션 생성과 수락 상태 변경은 하나의 트랜잭션입니다. 동시 수락 중 하나만 새 참여자를 만듭니다.
- 수락 후 같은 브라우저에서 다시 링크를 열면 유효한 기존 세션을 확인해 그 방으로 복귀할 수 있습니다. 다른 브라우저·기기, 쿠키 삭제, 세션 만료 후에는 새 초대가 필요합니다.
- 회원 인증과 별개로 초대 생성·재전송·수락에 단일 서버에서 관측한 IP당 15분 30회 제한이 있습니다. 여러 서버·프록시 운영은 별도의 공유 제한 설정이 필요합니다.

## 토큰과 쿠키

초대 토큰은 암호학적 난수이며 DB에는 SHA-256 해시만 저장합니다. 원문은 처음 생성·재전송 응답과 이메일에만 전달합니다. 초대 링크는 `/invite#token=...` 형식으로 웹 서버의 요청 URL이나 Referer에 토큰을 전달하지 않습니다. 내용 확인·수락 시 토큰은 POST 본문으로 보냅니다. 초대 페이지는 검색 색인을 차단하고 no-referrer를 지정합니다.

게스트 세션도 DB에 해시만 저장합니다. HttpOnly·SameSite=Lax 쿠키를 방마다 구분하며 운영에서는 Secure와 __Host- 접두사를 사용합니다. 쿠키 이름뿐 아니라 세션의 room_id, 연결된 참여자, GUEST 종류, 퇴장 여부와 만료를 매번 검사합니다. 방 ID나 쿠키 이름을 바꿔도 다른 방으로 접근할 수 없습니다. 회원 세션과 게스트 세션은 서로의 권한을 대신하지 않습니다.

초대 링크는 소지자가 사용할 수 있는 자격 증명입니다. 별도 이메일 소유 확인은 없으므로 링크를 전달받은 제삼자의 사용까지 차단하지는 않습니다.

## 이메일 발송

로컬에서는 `pnpm mail:up`으로 Mailpit을 띄우고 `http://localhost:8025`에서 메일을 확인합니다. 외부 주소로 실제 발송하지 않습니다. 개발 기본값은 MAIL_MODE=local, SMTP_HOST=127.0.0.1, SMTP_PORT=1025입니다.

실제 발송은 MAIL_MODE=smtp와 SMTP 호스트·포트·TLS·인증 정보·승인된 발신 주소를 환경변수로 설정합니다. 587 포트는 STARTTLS, 465 포트는 TLS 연결을 사용합니다. 운영 초대 링크는 허용된 HTTPS 웹 주소여야 합니다. 설정 예시는 apps/api/.env.example과 README.md를 참고하세요.

발송 상태는 SENDING, SENT, FAILED로 관리합니다. SENT는 SMTP 서버 접수이며 실제 수신함 도착·반송 추적은 별도입니다. 실패는 고정된 안내문으로 저장하여 비밀값·SMTP 응답 본문을 노출하지 않습니다. 서버 중단으로 SENDING이 남으면 1분 후 재전송할 수 있습니다. 이전 발송 작업이 늦게 끝나더라도 시도 ID가 다르면 새 발송 결과를 덮어쓰지 않습니다.

## API

| 경로 | 역할 |
| --- | --- |
| GET /api/v1/rooms/:roomId/invitations | 방장의 최근 초대 100건 조회 |
| POST /api/v1/rooms/:roomId/invitations | 이메일 초대 생성·발송 |
| POST /api/v1/rooms/:roomId/invitations/:id/resend | 링크 교체·재전송 |
| POST /api/v1/rooms/:roomId/invitations/:id/revoke | 미수락 초대 취소 |
| POST /api/v1/invitations/preview | 토큰으로 공개 초대 내용 확인 |
| POST /api/v1/invitations/accept | 표시 이름으로 게스트 참여 |
| GET /api/v1/guest/rooms/:roomId | 게스트 세션·방 정보 복원 |

쓰기 요청에는 허용된 Origin이 필요하고, 방장의 요청에는 회원 CSRF도 검사합니다. 일반 초대 목록에는 토큰·해시를, 공개 미리보기에는 수신 이메일을 노출하지 않습니다.

## 검증과 후속 작업

DB 통합 테스트는 일회용 스키마에서 권한, 만료·취소·재전송, 동시 수락, 세션 복원과 다른 방 접근 차단을 검증합니다. 브라우저 검증은 실제 Mailpit SMTP를 통해 발송 실패·재시도, 이메일 내용, 게스트 입장·새로고침, 사용·취소 링크 안내와 모바일 화면을 확인합니다.

메시지 조회·전송·Socket.IO 구독은 회원과 게스트 모두의 현재 참여 권한을 검사합니다. 수신 직전에도 권한을 확인하여 만료·퇴장·로그아웃한 세션에는 새 메시지를 전달하지 않습니다. 현재 참여자는 입장 전 대화를 포함한 해당 방의 전체 내역을 조회할 수 있습니다. 재연결 시 순번으로 누락분을 복구하며 같은 메시지 ID의 재전송은 중복 저장하지 않습니다.

참여자 차단 UI, 이메일 반송 웹훅, 다른 기기 복귀 정책과 모바일 초대·대화 화면은 별도 작업입니다.
